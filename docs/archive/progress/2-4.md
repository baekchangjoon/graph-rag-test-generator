# 2.4 — http-mock-composer + testlib WireMock 어댑터

## 진행 내용

- testlib: `HttpStubBuilder` API
  (`stub(method,path).withQueryParam().withBaggageTestId().respondJson().register()`)
  + `wiremock` 어댑터 — admin REST 직접 호출(의존성 0), 스텁에 testId metadata를
  남겨 `remove-by-metadata`로 scope 단위 제거. `HTTP_MOCK_ADMIN` 설정 시
  기본 어댑터가 wiremock (docs/07의 기본값 충족)
- generator `HttpMockComposer`: path의 CapturedHttpCall마다 스텁 등록 라인 합성.
  baggage 매칭은 `baggagePropagated`일 때만 (docs/04 격리 규칙)
- **병렬 안전 보고**: propagation 없는 path는 `@Execution(SAME_THREAD)` 마크 +
  `serial_required(SUT_PROPAGATION_MISSING)` (docs/06 parallel_safety_report)

## 검수

- testlib 단위 2건(매핑 JSON 형태/metadata 제거), generator 단위 2건
  (baggage 스텁 합성 / 직렬 마크) + 기존 골든 비회귀
