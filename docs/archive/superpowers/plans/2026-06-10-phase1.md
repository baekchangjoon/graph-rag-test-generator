# Phase 1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:executing-plans. 단계별 TDD + commit + progress 기록.

**Goal:** 분기 탐색(휴리스틱+퍼저+JaCoCo)과 MyBatis 지원으로 endpoint당 N path → N 테스트 통과.

**Spec:** `docs/superpowers/specs/2026-06-10-phase1-design.md`

### Task A: shared-model 확장
- `BranchRef(classFqn, method, line, branchIndex)` — JaCoCo 분기 좌표
- `ExploredPath`에 추가: `branchesTaken: List<BranchRef>`, `discoveredBy: String`,
  `constraints: List<String>`, `validationWarnings: List<String>` (기존 그래프와 전방/후방 호환:
  생성자 시그니처 변경이므로 라운드트립 테스트 갱신 + 빌더/제너레이터 컴파일 수정)
- `MapperStatement(id, namespace, statementId, sqlKind, dynamic, sourceXml)` + GraphAsset에 `mappers`
- `ExplorationReport(endpointId별 totalBranches/coveredBranches/missedBranches[BranchRef], engineStats)`
- 라운드트립 테스트 → GREEN → commit

### Task B: SUT MyBatis 확장
- 의존성: mybatis-spring-boot-starter 3.x
- `OrderSearchMapper`(@Mapper) + `resources/mappers/OrderSearchMapper.xml`
  (`<if test="userId != null">` 등 동적 SQL) + `POST /api/orders/search` 컨트롤러
- Testcontainers 테스트: 조건 조합 2개 이상 검증 → commit

### Task C (1.3): MyBatis 인덱서
- `MapperXmlIndexer.index(srcDir) -> List<MapperStatement>` — XML DOM 파싱,
  동적 태그(`if/choose/foreach/where`) 존재 → dynamic=true
- 단위 테스트(fixture XML) → commit

### Task D: JaCoCo 통합
- builder에 `org.jacoco:org.jacoco.core` + `org.jacoco.agent`(runtime) 의존
- `JacocoAgentAttachment`: agent jar 추출(AgentJar API) + JAVA_TOOL_OPTIONS 조립
- `CoverageClient`: TCP dump(reset 옵션), `ExecutionDataStore` 누적
- `BranchCoverageAnalyzer`: boot jar `BOOT-INF/classes` 분석 → 분기 총수 +
  covered/uncovered `BranchRef` 목록
- SutProcess에 extraJavaToolOptions/추가 로깅 레벨 파라미터
- 통합 테스트: 실제 SUT 기동 → 요청 1회 → dump에 분기 도달 확인 → commit

### Task E (1.1): PathExplorer SPI + 엔진 + 오케스트레이터
- SPI: `PathExplorer`, `EndpointTarget(endpoint, bodyShape, tables)`,
  `ExplorationBudget(maxRequests, maxDuration)`, `ExplorationResult(inputs+coverage)`
- `InputMutator`: 결정적 변이 카탈로그 (필드 누락/null/""/0/-1/미존재FK/대문자화 등)
- `HeuristicExplorer`: 변이 1단 적용 셋
- `CoverageGuidedFuzzer`: 시드 큐 + 변이 2단, novelty 기반 keep, 포화 K=8
- `ExplorationOrchestrator`: 엔진 리스트 순차 + 예산 슬라이스(빈 슬롯 양도) +
  포화 감지 + path dedupe(분기 집합 키) + discovered_by
- 단위 테스트: fake invoker/coverage로 오케스트레이션·포화·dedupe 검증 → commit

### Task F (1.2): ConstraintExtractor
- Spoon으로 handler 메서드 분기 조건 텍스트 수집 → path.constraints 첨부
- JDart 보류 decision doc (`docs/decisions/explorer-engines.md`) → commit

### Task G (1.4): MyBatis 로그 캡처
- `MybatisSqlLogParser`: `==>  Preparing:` / `==> Parameters:` (`값(타입)` 파싱,
  쉼표 포함 문자열은 타입 접미사 기준 best-effort) → ParsedSql 통합
- SutProcess: 인덱싱된 namespace를 TRACE 레벨로 SPRING_APPLICATION_JSON에 포함
- 단위 테스트(고정 로그) → commit

### Task H: PathCaptureRunner/BuilderCli 개편
- runner가 (입력, path메타) 단위 캡처로 일반화: seed는 입력의 FK 값 존재 시만,
  Hibernate+MyBatis 파서 병합, 분기/discovered_by/constraints 기록
- BuilderCli: 오케스트레이터 통합, `--budget-requests`(기본 60),
  `--manual-paths`, exploration-report.json 산출
- 통합 테스트: orders endpoint에서 path ≥3 (201/404/400) 발견 검증 → commit

### Task I (1.5): generator 다중 path
- `GenerationRequest.pathId == null` → 전 path, path당 클래스
  (`OrdersPostTest_PostApiOrdersHappy` 형식: testClassName + "_" + PascalCase(pathId))
- 404/400 path: fixture 0건, 상태코드+가능한 응답 필드 assertion
- 골든 테스트 확장(404 path 1건) + 결정성 → commit

### Task J: E2E + 문서 + push
- `e2e/run-phase1.sh`: build(탐색 포함) → 전 endpoint 전 path 생성 → compose →
  N개 테스트 전부 PASS 확인 (메트릭 기록)
- request.json 갱신(또는 phase1용 별도), e2e 모듈 그대로 재사용
- progress/1-*.md, decision docs, README 갱신, main push
