# 6.2 — 증분 빌드 인프라 (모듈/패키지 단위 파티셔닝)

- `IncrementalBuildPlanner`: 이전 그래프 + 변경 파일 목록 + 현재 인덱스 →
  재탐색 대상(`IncrementalPlan.exploreIds`)과 이월 사실 산출
  - 클린 파티션 endpoint: 이전 paths/sql/httpCalls/wsExchanges 이월 (재탐색 생략)
  - 더티 파티션·이전 탐색 없는 endpoint: 재탐색
  - 삭제된 endpoint 사실은 이월 제외 (현재 정적 인덱스 기준 필터)
  - 매핑 불가 변경(XML 등) → 전체 재탐색 (보수적 폴백)
- `BuilderCli`: `--incremental-base <prev-graph-dir> --changed-files <list-file>`
  (git diff --name-only 출력 파일). 옵션 없으면 기존 풀빌드와 동일
  (`IncrementalPlan.exploreAll()`)
- 이월분은 manual paths 병합 전에 합쳐 수동본 우선 규칙 유지
- 검수: 플래너 단위 5건 GREEN (클린 이월/더티 재탐색·삭제 제외·신규 탐색·
  폴백·풀빌드), 전 모듈 단위 테스트 GREEN
- 정적 인덱싱(endpoint/mapper)은 항상 풀로 수행 — 비용은 동적 탐색에 집중되므로
  증분 범위를 탐색으로 한정 (docs/10 증분 인덱싱 알고리즘의 PoC 축소판)
