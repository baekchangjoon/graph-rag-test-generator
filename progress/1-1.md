# 1.1 — PathExplorer SPI + 자체 fuzzer + JaCoCo

## 진행 내용

- `PathExplorer` SPI + `ExplorationOrchestrator` (docs/05): 엔진 순차 실행,
  totalBudget(요청 횟수 주예산 + 시간 cap) 슬라이스 분할(첫 엔진 cap 50%,
  미사용분 양도), 엔진 간 KnownCoverage 누적, 분기 집합 dedupe, discovered_by 보존
- `HeuristicExplorer`: happy + 1단 boundary-value 변형 (결정적 순서)
- `CoverageGuidedFuzzer`: novelty 시드 환류(2단+ 조합), 포화 감지(연속 16회
  novelty 없음 → 조기 종료), 동일 body 재시도 방지
- JaCoCo: agent를 env(`JAVA_TOOL_OPTIONS`)로 부착, 요청 단위 TCP dump(reset) →
  boot jar `BOOT-INF/classes`만 분석해 SUT 분기 novelty 판정
- **path 식별 = 응답 status + 분기 집합**: Optional 내부 등 라이브러리 분기는
  분석 범위 밖이라 분기 집합이 같아도 status가 다르면 별개 path로 취급

## 검수

- 오케스트레이터 단위 테스트 5건 (fake invoker: 3-path 발견/결정적 id/예산 준수/
  엔진 기록/커버리지 누적)
- 실 SUT 통합: orders endpoint에서 201/404/400(6변형) 발견.
  search의 400(필터 전부 제거)은 **fuzzer의 3단 변이로 발견** — 휴리스틱 1단
  한계를 fuzzer가 보완하는 docs/05 구조가 실측으로 입증됨
